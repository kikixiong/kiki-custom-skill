# Idea 调研方法（S3 与 S9 用）

本方法改编自本机三个 skill，换成了有 verifier 打分的竞赛场景：
- `brainstorming-research-ideas`：发散 → 收敛 → 精炼三段式，以及"选哪个框架"的对照表；
- `creative-thinking-for-research`：约束操纵、否定与反转、相邻可能；
- `idea-evaluator`（改编自 HKUSTDial/Supervisor-Skills，CC-BY-4.0）：先查致命缺陷再打分、范式转变探针、四类可行性风险。

和写论文时的区别有三点。
- 判据只有一个：经官方 verifier 复验的 ΔGM。
- 打分不用"更高、更快、更强"五维，改用"收益 × 概率 ÷ 投入"。
- 每个 idea 都必须带上它最便宜的否证检查。

## 阶段 1：发散（每个子任务产出 10–20 个候选，先不过滤）

每个子任务至少用 4 个透镜。每个透镜后面附了本次战役里的真实例子，方便判断什么叫"用对了"。

| 透镜 | 竞赛版问法 | 战役中的真实例子 |
|---|---|---|
| **成本公式张力** | 成本公式里哪两项在互相拉扯？在汇率下哪边更便宜？ | DQI 成本 R×Q²×T：Q 是平方项，1 qubit 约值 815 T。对手用 891Q、多花 2.5 万 T 照样赢 |
| **隐藏约束清单**（约束操纵） | 列出我们默认不能动的东西，逐条标"硬约束 / 软约束 / 只是习惯" | 我们默认"62Q 不能动""反算必须全量镜像""889 上限只往上扫"，这三条其实都是软约束 |
| **否定与反转** | 把一条软约束取反，会得到什么电路？ | 把镜像反算换成"测量 + 条件相位修正"：invsqrt 从 97,922 降到 86,217（-12%） |
| **下界与边界** | 当前这一族电路的下界是多少？离它还有多远？方法在哪里失效？ | 旧 invsqrt 族的下界约 11 万，再微调也到不了，必须换族 |
| **What changed** | 自上次外循环以来，出了哪些新 notebook、队友分支、主办方裁定、论文？ | 主办方裁定"ANGLE 只需在可达态上正确"，于是借用符号位变得合法 |
| **领先者反推** | 用榜单算术反推榜首每个子任务至少要做到多少倍 | 榜首 28.49 意味着化学至少要 13.4×，而 brot 8 只剩约 5%，所以榜首几乎必然在用 brot ≤ 7 |
| **跨领域迁移** | 相邻领域里有没有结构相同的问题？迁移前先写清映射 | QROM 的测量式 unlookup（Berry、Gidney 等）、DSP 过采样 → twin rows |
| **组合与拆解** | 能不能把两个已有杠杆叠起来？能不能按子任务拼出组合包？ | 拼装队友的 invsqrt、DQI 和化学：本地 GM 24.80 → 26.16 |
| **表示层级阶梯** | 同一个想法放在门级、生成器参数、算法、数据表示四层里，分别是什么样子？ | 化学：逐字 bit-1 编码（我们）→ 五字 XOR 编码（Lera） |

发散阶段的纪律：
- 被否掉的候选也要留在列表里，标注原因。它们以后可能和别的想法重新组合。
- 至少一半候选必须来自前五行透镜，也就是结构性的。只写"调参数"的列表不算完成发散。

## 阶段 2：收敛（筛到每个子任务 3–5 个）

### 2a 致命缺陷审查（先于打分；有一条 CRITICAL 就停止评估）

| 缺陷 | 级别 | 竞赛版判据 |
|---|---|---|
| 违规或利用盲区 | CRITICAL | 只因 verifier 抽样没覆盖才通过、刷 salt、改 verifier、依赖数据比特的条件 |
| 被现成组件支配 | CRITICAL | 公开或队友已有更好的同类组件，直接拼装就行 |
| 低于盈亏线 | CRITICAL | 按汇率表算出来不赚（例：CAP+1 最多省 4.5 T，需要 19.8 T 才回本） |
| 无法精确验证 | MAJOR | 不能在全域或九盐上复验，只能靠抽样估计 |
| 算力或时间不现实 | MAJOR | 超出资源上限，或超过截止前剩余的外循环次数 |
| 依赖缺失 | MAJOR | 例：改系数表需要 plan 搜索脚本，交付包里没有 |

### 2b 两句话测试

> "**[子任务] 的成本被 [某一项] 卡住，因为 [机制]。** 我们改 [什么]，预计省 [N]（按汇率等于 [x%]，即 [ΔGM]），因为 [洞见]。"

写不出这两句话，说明 idea 还不清楚，退回阶段 1。

### 2c 定价表

每个幸存的 idea 填一行，按 E/天 排序：

| idea | 子任务 | 成功时降幅 | ΔGM | p | 期望 ΔGM | 预计 agent-天 | E/天 | GPU/CPU | 最便宜的否证检查 |
|---|---|---:|---:|---:|---:|---:|---:|---|---|

### 2d 范式转变探针

对排名前 5 的 idea 各问四个问题：
1. 它是否打破了一个隐藏约束？
2. 它是否在解决大家回避的那块最大成本？例：step2_inv 的 215 T 镜像反算。
3. 有没有新工具、新裁定或新组件让它刚刚变得可行？
4. 成功之后，下一轮的 backlog 会不会因此改写？

Top-5 里至少要有一条得到 ≥ 2 个"是"。做不到的话，回阶段 1 补结构性候选。

### 2e 四类可行性风险

算力、数据或依赖、工程、时间，各给一个风险等级。每个高风险都要写出具体的缓解办法。

## 阶段 3：精炼（交给 S4 预注册）

1. 写好两句话 pitch。
2. 写出最便宜的否证检查，并给出它的 kill 判据，例："一小时内找不到 ≤ 24 AND 的电路就停"。
3. 写决策表：结果落在每个区间时分别怎么做。
4. 提前写出最强的反对意见，并准备好回应。
5. 说明需要读的文件、需要先测的量（例：先测每个阶段的平均 Toffoli 和 qubit 峰值，再改电路）。
6. 把结果写成 `experiments/<slug>/protocol.md` 的草稿。

完成清单：
- [ ] 两句话 pitch 成立
- [ ] 致命缺陷审查通过
- [ ] 有数值价格和盈亏线
- [ ] 有否证检查和 kill 判据
- [ ] 决策表覆盖所有结果区间
- [ ] 每个子任务的列表里至少有一条结构性条目

## 透镜选择对照

| 处境 | 先用 |
|---|---|
| 刚开赛，只有基线 | 成本公式张力 → 领先者反推 → 下界与边界 |
| 连续几轮每步收益 < 0.3% | 隐藏约束清单 → 否定与反转 → 表示层级阶梯 |
| 榜单突然跳一大截 | What changed → 组合与拆解（先拉公开 notebook 和队友分支） |
| 手里有个新技巧 | 两句话测试 → 致命缺陷审查（先查它在别的子任务能不能用） |
| 旋钮全扫完没有收益（例：86217 生成器的 46 个旋钮都在局部最优） | 范式转变探针 → 找最大的那块成本，重写它的算法 |

## 常见陷阱

| 陷阱 | 症状 | 解法 |
|---|---|---|
| 默认增量 | backlog 里全是 +0.1% 的微调 | 跑隐藏约束清单，强制补结构性条目 |
| 回音室 | 所有 idea 都来自自己的旧实验 | 重跑 S2：公开 notebook、队友分支、论坛 |
| 过时假设 | "这个以前试过不行"，但条件已经变了 | 用 What changed 透镜重新检查 |
| 只扫一个方向 | 参数只往一边扫过 | 把反方向写进候选（例：889 上限从没向下扫过） |
| 外推宣判 | 看了探针就判死刑 | 跑完才判；探针只用来排序 |
| 过早收敛 | 第一个想法就开干 | 每个子任务先凑满 10 个候选 |
| 把"可用"当"更好" | 拼进来的组件没和现有组件逐题比较 | 按子任务做三方对比：公开、队友、我们 |

## 给 agent 的用法

- **发散**：交给研究型 agent（Opus 级），每个子任务一个 agent 并行。brief 里写明要用哪 4 个透镜、已排除的方向，以及当前汇率表。
- **收敛**：交给另一个独立 agent 做批评，不给它设计者的结论。它负责致命缺陷审查和定价复算，Orchestrator 再自己抽查一处数字。
- **决策**：由 Orchestrator 拍板，向用户汇报 Top-3 及理由。用户明确说过的方向优先。
- 候选全集写入 `literature/distill/<round>_ideas.md`，排序后的结果写入 `SYNTHESIS.md`。
