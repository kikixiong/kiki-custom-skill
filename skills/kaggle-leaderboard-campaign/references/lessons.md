# 战例与规则

每条：发生了什么（来源） → 由此产生的规则。来源指原项目（一次 Kaggle 量子电路编译赛战役）里的 research-log 行号或文件，仅供溯源；原项目不随本 skill 分发。

## A. 指标与统计

1. **先逐位复现，再优化。** 第一天用原样官方 verifier 写评测壳，本机与集群都复现基线 23.90600，并与公开榜
   23.91005 校准（log 1–2，`research-state.yaml: official_scores`）。→ 代理指标未逐位对上之前不做任何优化。
2. **基线本身就带运气。** DQI 基线的九盐成本偏幸运，期望成本约 3.796e11（`findings.md`）。DQI-G3 的 -0.121% 里只有
   -0.019% 是结构性的，其余是失败次数的运气（2 值错 vs 4 相位错；配对 seed 下两者在同 5 个 shot 上失败）。
   → 多盐均值 + 配对 seed 拆分结构收益与运气；永不挑最幸运的 salt。
3. **失败有价格。** 测得 R=1.1913（无失败），1 次失败 +0.46%，10 次 +3.2%，50 次 +10%（`findings.md`）。
   → 把“有代价地容忍罕见失败”当作可定价的合法杠杆，但每一次观测到的失败都照实计入。

## B. 预注册与判死

4. **探针判死被用户否决。** CHEM-BROT7 先按 stage-5 比率和外推被关，用户：“这个方法你可以用 gpu 完全做完再判断”
   （log 64，本地记忆）。完整运行后结论（23.22 mHa > 20 门槛）才是定论（log 135）。
   → 协议里写“跑到最终官方数字”；探针只用来排序。
5. **协议写在下载之后 / 修正写在验证之后。** 早期 wave-1 评审指出协议晚于下载（log 18）；DQI 重写评审发现
   Amendment 在 D 验证后才定稿（log 35）。→ 协议时间戳必须早于第一个作业；Addendum 只能细化，不能放宽 kill。
6. **更正而非改写。** log 187 宣布 SFS-55“正式解锁”（402 AND < 416 门槛），log 188 更正：方案需要 9 输出的 M_RE9
   （103 AND），合计 427，落在需非 lookup ≤ 935 的区间，而实测 974.75，**未解锁**。→ 结论要对照协议决策表逐项核；
   错了写 `correction` 行指回原行。
7. **崩溃不是负结果。** DQI 负 bonus 扫描四个 build 均在 1 秒内被 `assert 0 <= BONUS <= 64` 拦下，未产出任何电路
   （log 204）；此前驱动脚本的正则 `^[0-9]+:[0-9]+$` 也不接受负号（log 201）。→ 扫参前读脚本自身的 assert、正则和
   flag 前置条件；结果分“正/负/未被检验”三类记。
8. **flag 前置条件。** PP4 因 `--free-tail needs padding rows` 失败：R12/B111 行数整除无余（log 194）。→ 同上，
   提交前对每个 flag 核对适用条件。
9. **QAT 参数量级错。** λ=2e-3 使 error_2 从 14.61 恶化到 661 mHa，λ=5e-3 到 802（log 200, 204）。→ 先做量级定价
   （惩罚项相对主损失的尺度），新超参从保守端扫起。

## C. 定价与汇率

10. **汇率错 6 倍。** 给子 agent的 brief 写“10 Toffoli ≈ 0.12%”，agent复算为 0.77%（成本对 G_eq 线性，
    `experiments/mbu-ideas/invsqrt86217.md` §0）。→ brief 里的汇率要附算式；agent必须复算并报告差异。
11. **盈亏预算揭示从未试过的方向。** DQI 宽度调研算出 Q=914 时 1 qubit = 814.8 T，Q 降到 880 可多花 29,329 T，
    并发现所有宽度门控 kernel 硬编码 889 上限、历史上只向上扫（log 198）。→ 对每个资源维度写出交换率和盈亏预算，
    再看历史扫描是否只覆盖了一侧。
12. **定价杀掉无收益的想法。** MBU（测量式反算）用于化学 ANGLE 与 DQI：桌面研究即得出 ≤0.27% DQI、化学基本无空间
    （log 205, 207）。→ 先读 verifier 的计数方式（执行次数 vs 静态次数）再定价，便宜地关掉方向。

## D. 局部最优与结构性收益

13. **数天微调，收益递减。** invsqrt 在 C6 族内的局部重综合、Horner-2、burst exchange、LUT3-FLIP 等相继关闭，
    每步 ≤0.3%（`research-state.yaml` INV-C6-LOCAL、LUT3-FLIP；log 158–162）；DQI 族内每个杠杆 ≤ ~0.25%（`findings.md`）。
    → 当最好 idea 的价格 < 0.5% 时触发外循环。
14. **大收益来自结构与拼装。** 队友的从零生成器用“HMR 垃圾、仅在结果位为 1 的分支上修相位”替代镜像反向 Horner，
    invsqrt 97,922 → 86,217（约 -12%，`experiments/mbu-ideas/dqi.md` 触发段，log 206）；把它与队友的 DQI、公开的
    化学组件拼装并九盐复验，组合分约 26.16（log 206–209），而此前最好的推送（gm24.811）是 24.80。
    → 外循环必须包含：不同架构的一条线 + 按任务拼装所有最好组件并复验。
15. **榜单算术。** 领先者三题乘积约 25,155，我们约 17,895，需 ×1.41（log 209）；早先算出 28.49 需要化学 ≥13.4×，
    推断领先者用 brot ≤7（`literature/distill/MOONSHOTS.md`）。→ 用榜单反推“领先者必然做了什么”，指导方向选择。
16. **少调研，多迭代。** 多轮 moonshot / 跨领域调研后用户要求“少点调研……尽快开始跑多点迭代”（memory
    `prefer-iteration-over-research`）。→ 调研只在执行被具体问题卡住时开，跑完立即转为实验。

## E. 情报与第三方代码

17. **公开代码会追上来，也会落后。** 11-10 快照：公开最高约 25.23，我们的组合 26.16，公开化学只低 0.054%
    （log 209）。→ 每周（窗口期每天）拉榜和新 notebook，分任务 diff，只吸收真正更好的组件。
18. **文件隔离不够，要断网。** 探针作业证明集群容器可访问 kaggle.com，于是沙箱改为 `unshare -rn` + fail-closed
    出网检查（作业提交器的文档与本地记忆）。→ 第三方代码：REVIEW.md 批准 →
    只挂载其目录的断网沙箱 → 产物当不可信数据，用我们自己的 eval 在单独作业中验证。
19. **审查要复核。** invsqrt-86217 的 REVIEW revision 2 由主 agent用 grep 遍历全部 .py 独立复核（动态导入只有固定的
    兄弟模块名、唯一写文件是输出电路、无网络/子进程/exec/pickle）（`sandbox/invsqrt-86217/REVIEW.md`）。
    → 安全审查结论进入执行前，Orchestrator 亲自抽查。
20. **字节级闭环。** DQI G2 从公开生成器 + 我们的补丁 + 后处理在沙箱中逐字节重建，17/17 哈希链吻合
    （`experiments/dqi-g3/protocol.md` S0）。→ 进入最终提交的组件必须有可运行的生成源码，哈希逐环核对，
    任一环不符就停在那一环。

## F. 基础设施

21. **共享存储供陈旧文件。** 原地重写的脚本被集群 pod 读到 3 小时前的旧版；追加写的文件关闭前不可见；仅大小写不同的
    文件名不可靠（`findings.md`）。→ 每个新版本换新文件名或在 pod 内校验 sha256。
22. **作业比agent活得久。** 两个agent因 API 额度耗尽同时失败，它们的集群作业仍在跑（log 182）；还出现过来源未登记的
    遗留作业（log 204）。→ 作业 id 立即写入 state 的 `active_experiments`，任何人都能接管或清理。
23. **别给运行中的工作流agent发消息。** SendMessage 复活了第二个实例，重复写 Addendum 并重复提交作业（log 70）。
    → 只通过工作流自身机制与其中agent沟通。
24. **权限拒绝不代办。** 子 agent的 取消集群作业 被权限系统拒绝，Orchestrator 不代为执行，转交用户（log 143）。
25. **本机是共享机器。** 一次评审发现子 agent在本机跑了 14 次全尺寸分析、在 /tmp 解出 1.4 GB（log 35）。
    → 重活一律经提交器上集群；本机只做编辑和轻量检查。

## G. 发布与对外

26. **git 身份损坏。** 全局 git email 被写坏（多了 'ni' 与一个杂散字节），提交在 GitHub 上显示为未关联用户，事后需带
    lease 强制更新四个分支（log 62, 66）。→ 提交前检查 `git config user.email`。
27. **推送门槛与先汇报。** 用户定：增益 < 0.05 先不推，累积后合并推送；每个改进先汇报；新分支从 `main` 开、永不提交
    `main`；用户明确要求可越过门槛（gm24.451，+0.0497）（本地记忆）。
28. **对外动作需批准。** 榜单提交、公开 notebook、组队/合并、联系他人都要用户明确批准（memory
    `qc-kaggle-submission-and-prizes`）；公开 notebook 会把方法交给对手，汇报时要写明这一代价。
29. **算力上限写进工具。** 上限经历 80 → 180 CPU → 取消固定上限、只保留“≤ 集群总量一半”，均由提交器加锁统计后
    强制执行（作业提交器）。→ 资源规则写成代码，不靠记忆；超出仍需问用户。
